## Residual findings

### [HIGH] Persisted bootstrap matrices are not checked against the registered deterministic RNG seed

`_read_bootstrap_matrix()` validates family keys, exact IDs, row/column shape,
range, and file hash, but it does not require the matrix to equal the matrix
generated by the registered seed 9047 (accuracy) or 9157 (retention)
(`report.py:750-788`). The actual gate producer uses
`np.random.default_rng(seed)` to generate these matrices
(`gates.py:827-830`, `gates.py:889`); a persisted matrix is therefore a
scientific input, not merely a shape-checked index list.

Independent direct probe used 100 IDs per family, with only one A2-vs-control
correctness improvement per seed. The true per-seed and two-seed macro gain is
approximately `0.0033`, below the registered `0.02` threshold. A fabricated
matrix that sampled the one positive expression ID on every one of 10,000
replicates nevertheless produced an accepted raw-derived vector:

```text
BIASED_NONREGISTERED_MATRIX_ACCEPTED True 0.3333333333333333
```

The report must regenerate the exact family-keyed matrix from the registered
seed and compare it (or persist and verify its canonical matrix digest), so a
biased but hash-consistent matrix cannot manufacture a passing CI/point.

### [HIGH] Retention bootstrap evidence is still not represented per seed

The report calls `_has_registered_bootstrap()` once for retention seed 9157
and `_derive_bootstrap_comparisons()` averages the seed-47 and seed-48 sampled
ratios into one vector (`report.py:697-704`, `report.py:878-917`). The actual
`paired_retention_bootstrap()` producer returns one vector/point/CI for one
candidate/F0 chunk pair (`gates.py:871-906`), while the registered confirmation
gate requires both seed-specific PPL points and upper endpoints
(`gates.py:967-983`). The current report does independently enforce the full
ratio threshold per seed, but it does not persist/read/hash/recompute two
seed-specific bootstrap vectors and CIs or reconcile each seed's reported
point/upper bound. A single averaged CI is not evidence for both registered
seed intervals.

### [MEDIUM] Training-failure event identity is still optional and failed-environment linkage can cross arms/seeds

The per-kind training-failure schema requires only `attempt`, `message`,
`error_type`, and `cuda_process_fault`; `stage`, `arm`, `seed`, `update`,
`event_id`, and payload are allowed but not mandatory (`report.py:1151-1178`).
This malformed failure was accepted:

```json
{"index":0,"timestamp":"2026-09-18T10:00:00+00:00",
 "kind":"training_failure","attempt":1,"message":"x",
 "error_type":"E","cuda_process_fault":false}
```

Further, a `failed_environment` event for A2/48 referencing a training failure
for A1/47 was accepted (`MISMATCHED_FAILURE_ID_ACCEPTED`). The validator checks
referenced kinds, indexes, and attempts but does not reconcile stage/arm/seed
identity or validate the failure event ID. This permits incomplete or
misattributed failure history even though the event is syntactically valid.

### [LOW] Windows descriptor path leaks intermediate final-file handles on nested paths

In the Windows branch, the final `_open_nt(absolute.name, parent_handles[-1],
...)` call is inside the loop that checks every parent component
(`report.py:330-340`). For a nested path it opens the final file once per
parent but converts/closes only the last handle. The read result is still from
the trusted final handle, so this is not an escape, but repeated report reads
can leak one native file handle per nested parent component.

## Overall decision

**FAIL — Task 14 is not ready for acceptance.** Round five closes the prior
per-seed macro, full retention-point, Windows path-resolution, timestamp, and
event-type/range gaps. However, a hash-consistent but non-registered bootstrap
matrix can still bias the reported CI into a success, retention bootstrap
evidence is averaged across seeds instead of represented per seed, and failure
events can lack identity or cross-link to a different arm/seed. These remain
scientific anti-fabrication and provenance failures.
